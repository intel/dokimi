### Fixed

- **`process:guidance_read` and `guidance_searched` follow a `..` after a link as the system does** — `cat alias/../AGENTS.md` and `grep warn alias/../AGENTS.md` with `alias -> docs/nested` open `docs/AGENTS.md`, but the converter collapsed the `..` by name and `repo run` credited `AGENTS.md`; with `sub/alias -> /outside/nested` it credited `sub/AGENTS.md` for a file outside the workspace. The converter now keeps a `..` after a name in the `path` of a `read` event, in `searched` (`cd alias && cat ../AGENTS.md` is `alias/../AGENTS.md`), dropping only `.` components and repeated `/` from a relative path it joins to the working directory (an absolute path, or a relative one with no working directory known, is kept as written); a `cd` still takes its own `..` by name, as bash does, unless it is `cd -P`. The process metrics resolve it against the links the workspace had at the start, so the listed path is the file the system opens (`docs/AGENTS.md`) and nothing is credited when it is outside the workspace. A `..` after a plain directory still lists the normalised file (`src/../AGENTS.md` is `AGENTS.md`), and the last name of the path is kept as written, so `src/../AGENTS.md` with `AGENTS.md -> docs/guide.md` is still `AGENTS.md`, the name the guidance globs match. Events stored with a collapsed path read as before; a new `read` event can now hold `sub/../AGENTS.md` where it held `AGENTS.md`, and `shell_reads("cd sub && cat ../AGENTS.md")` returns `sub/../AGENTS.md`.
