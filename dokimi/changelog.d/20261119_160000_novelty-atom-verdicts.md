### Added

- **`skill novelty analyze` saves each atom's judged and measured verdicts beside the artifact, and `skill novelty view --atom-verdicts FILE` colours spans from them** — `analyze` now writes `<out stem>.atom_verdicts.json` (`novelty.atom_verdicts.json` beside `novelty.json`), a new `novelty_atoms` artifact (`novelty_atoms.v1`), and prints `OK Saved atom verdicts:`. It has one row per atom the run probed (a capped run's sample) with `id`, `statement`, `question`, `answer`, `kind`, `tags`, `span_ids`, `faithfulness`, the judged `needed`, `scaffolding`, `conflict` and `conflict_why`, the measured paired `outcome` under `lenient` and `strict` scoring, and the content `category`, plus the run's `with_arm` and its `conflicts` pairs. The judged fields and `category` are `null` for a run with `--no-classify` or a tier without classification, and `outcome` is `null` for an atom with no usable pair. A file left by an earlier run into the same output is overwritten. `novelty.json`, `novelty.md` and the annotated view are unchanged. `view --atom-verdicts` re-renders the annotated view with outcome and category colours with no model call, and exits 2 for a file written beside another analysis (a different `artifact_ref`) or naming atoms the `--atoms` file does not hold; without the flag `view` colours by span structure and category as before.
