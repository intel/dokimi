### Added

- **`catalog routing` takes acceptable alternative skills per query, and `catalog routing-compare` compares two saved runs** — in the `--queries-by-skill` file a request may be an object `{"query": "...", "acceptable": ["other-skill", ...]}` beside the plain strings. A file of strings reads and saves as before. When the file names at least one alternative, each arm adds `acceptable_rate` per gold skill beside `own_rate` (the gold or an acceptable skill picked, over the same scored queries), the summary prints it, and the rows of such a query keep `acceptable`; `confusion` and `attractors` still follow the gold alone. An `acceptable` that is not a list of strings, an object without a string `query`, an unknown key, or an acceptable name outside the field is refused with the file, skill and query. `catalog routing-compare BASE.json OTHER.json [--arm lexical|model] [--out FILE]` pairs the per-query rows of two saved runs by `(gold, query)`, makes no model call, and reports each run's number right, the queries right in one run only, the exact two-sided sign test over the distinct `(gold, query)` queries right in one run only (a request listed twice counts once), and the queries whose pick changed. A saved row of the wrong type (`query`, `gold`, `acceptable`, model `picks`) is refused naming the file and row. The comparison file has no JSON Schema, as `catalog routing --out` has none.
