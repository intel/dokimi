### Fixed

- **Library callers get a named refusal, not a traceback, for some malformed saved answer keys** — `check_answer_key` and `entry_point_only` in `dokimi.novelty.bundle` now read the saved bundle block once into a typed record. A `files` value that is not a list, or a file row that is not an object, gets the `without usable file rows` verdict from `check_answer_key`, or the `without file rows` error from `entry_point_only` when it is the entry point. Where either used to raise a bare `TypeError`, `AttributeError` or `KeyError`, the change is as follows. With `include_resources` true, a malformed `excluded` list (not a list, or a row that is not an object with a string `path`) gets the `without usable file rows` verdict of `check_answer_key`, naming the excluded list, where it used to be read as empty or to raise. Without `include_resources` the list is not read, as before. An entry point with no `path` gets a named `ValueError`. Other malformed shapes still raise as before: a list-valued budget or `words: null` on a bundled row with no budget. The CLI loader (`atoms`, `probe`, `shorten`) refuses all of these at load, so CLI output is unchanged, and so is every record that was already read correctly.
