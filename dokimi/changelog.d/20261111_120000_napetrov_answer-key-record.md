### Fixed

- **Library callers get a named refusal, not a traceback, for some malformed saved answer keys** — `check_answer_key` and `entry_point_only` in `dokimi.novelty.bundle` now read the saved bundle block once into a typed record. A `files` value that is not a list, or a file row that is not an object, gets the `without usable file rows` verdict from `check_answer_key`, or the `without file rows` error from `entry_point_only` when it is the entry point. Where either used to raise a bare `TypeError`, `AttributeError` or `KeyError`, the change is as follows. A non-list `excluded` value is read as empty and a non-object entry in `excluded` is ignored. An entry point with no `path` gets a named `ValueError`. Other malformed shapes still raise as before: a list-valued budget, `words: null` on a bundled row with no budget, or an unhashable `excluded` path. The CLI loader (`atoms`, `probe`, `shorten`) refuses all of these at load, so CLI output is unchanged, and so is every record that was already read correctly.
