### Fixed

- **`process:guidance_read` lists only guidance files the workspace held when the agent started** — a Bash call that holds several reads (`cat a/AGENTS.md; cat missing/AGENTS.md 2>/dev/null`) gives each of them `rc` 0, since its exit does not say which file failed, so `guidance_read` listed a path that never existed. `repo run` now takes the workspace files `guidance.globs` match after the arm is applied and before the agent starts, and keeps a read only when its path is in that set: a path that never existed, a file the arm removed and a file the agent created itself no longer count, and a path through a link to a held file (`alias/AGENTS.md` with `alias -> docs`) does, by the links of the start (removing or retargeting the link later unlists nothing), while a link that dangles is no held file. A read of a file that is there, the `rc` rules, `unknown_reads` and `tool_calls` are unchanged. A probe path pattern (`/proc/cpuinfo`) on a file that a `grep` or `rg` names after a short option with an attached value ending in a value option's letter (`rg -g*.md x /proc/cpuinfo`) was missed.

### Added

- **`process:guidance_searched` lists the guidance files an agent searched** — `process.guidance_searched` in `result.json` holds the sorted guidance paths (held when the agent started, as for `guidance_read`) that a `grep`, `egrep`, `fgrep`, `rg` or `git grep` part of a Bash call (Claude Code), command (Codex) or `bash` command (Copilot) named as a file operand and showed lines of, and the path of a Claude Code `Grep` call in `content` mode. `guidance_read` keeps its meaning (files printed whole) and `tool_calls` its count. Not counted: `-q`, `-l`, `-L`, `-c`, `--count`, `--files`, a directory or glob operand, stdout sent to a file, a negated or refused command, a pipe into anything but a `head` or `tail` that passes lines (`head -n 0`, `--help`, a shell function of that name do not; `2>/dev/null` on it changes nothing), and a search that failed as one search of one file. A relative file after an earlier call's `cd` is dropped and is not added to `unknown_reads`. The `command` and `tool` events carry an optional `searched` list (`repo_event.v1` widened, `docs/events-format.md`), and `repo compare` and `repo report` show a `process:guidance_searched` row beside `guidance_read`. A relative `path` of a `Grep` call starts at the directory the harness started in (`sub/AGENTS.md`, not `AGENTS.md`); a `grep` option written as an unambiguous prefix (`--qui`, `--cou`, `--exclude-d AGENTS.md`, where `AGENTS.md` is the option's value) is read as the option it abbreviates, `rg` ones are not; a `Grep` result that is empty or says `No matches found` searched nothing; a link that loops back through a `..` component (`alias -> alias/../docs`), or whose target goes `..` out of a name that was no directory at the start (`alias -> missing/../docs`), or whose target is on another drive (Windows), leads to no held file; a command whose result is the empty text (`grep x AGENTS.md | head` with no match exits 0) searched nothing; and a `tail` with an invalid value (`--follow=bad`, `--pid=x`, `-s x`), a `--follow=name` (refused for its input) or a count that is not a number is not a stage that passes lines. A command whose searches are all in its last part (`grep x AGENTS.md docs/AGENTS.md`, `echo hi; grep x AGENTS.md`) that exits 1 (any error, for Claude Code) matched no line in any file, so it lists none; a relative `Grep` path after a Bash call that may have moved the shell is dropped, as a relative `grep` is; `grep -V`, `rg -V` and `rg -h` print the version or help and search nothing; `| /usr/bin/head`, `| LC_ALL=C head`, `|& head` and `git --no-pager grep` (`-P`, `-c k=v`) are counted as `| head` and `git grep` are; and the held files compare as the platform folds case, so `DOCS/AGENTS.md` is held where `docs/AGENTS.md` is on Windows. The closing `}` of a brace group is no last part (`echo hi; { grep x AGENTS.md; }` that exits 1 lists none); an `rg --passthru` (or `--passthrough`) that exits 1 printed every line of its files, so it keeps them, unless it shows none (`-q`, `-c`); a `head`/`tail` count or `-m` value of thousands of digits is read, not an error; a search before the last part keeps its files when a later computed `cd` loses the directory of the last part (`grep x AGENTS.md; cd "$D"; grep y docs/AGENTS.md` that exits 1); and an absolute Windows `Grep` path (`C:/ws/AGENTS.md`, `C:\ws\AGENTS.md`) after a Bash `cd` stays searched, as a POSIX one does.
