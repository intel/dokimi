### Fixed

- **`process:guidance_read` lists only guidance files the workspace held when the agent started** — a Bash call that holds several reads (`cat a/AGENTS.md; cat missing/AGENTS.md 2>/dev/null`) gives each of them `rc` 0, since its exit does not say which file failed, so `guidance_read` listed a path that never existed. `repo run` now takes the workspace files `guidance.globs` match after the arm is applied and before the agent starts, and keeps a read only when its path is in that set: a path that never existed, a file the arm removed and a file the agent created itself no longer count, and a path through a link to a held file (`alias/AGENTS.md` with `alias -> docs`) does, by the links of the start (removing or retargeting the link later unlists nothing), while a link that dangles is no held file. A read of a file that is there, the `rc` rules, `unknown_reads` and `tool_calls` are unchanged. A probe path pattern (`/proc/cpuinfo`) on a file that a `grep` or `rg` names after a short option with an attached value ending in a value option's letter (`rg -g*.md x /proc/cpuinfo`) was missed.

### Added

- **`process:guidance_searched` lists the guidance files an agent searched** — `process.guidance_searched` in `result.json` holds the sorted guidance paths (held when the agent started, as for `guidance_read`) that a `grep`, `egrep`, `fgrep`, `rg` or `git grep` part of a Bash call (Claude Code), command (Codex) or `bash` command (Copilot) named as a file operand and showed lines of, and the path of a Claude Code `Grep` call in `content` mode. `guidance_read` keeps its meaning (files printed whole) and `tool_calls` its count. Not counted: `-q`, `-l`, `-L`, `-c`, `--count`, `--files`, a directory or glob operand, stdout sent to a file, a negated or refused command, a pipe into anything but a `head` or `tail` that passes lines (`head -n 0`, `--help`, a shell function of that name do not; `2>/dev/null` on it changes nothing), and a search that failed as one search of one file. A relative file after an earlier call's `cd` is dropped and is not added to `unknown_reads`. The `command` and `tool` events carry an optional `searched` list (`repo_event.v1` widened, `docs/events-format.md`), and `repo compare` and `repo report` show a `process:guidance_searched` row beside `guidance_read`. A relative `path` of a `Grep` call starts at the directory the harness started in (`sub/AGENTS.md`, not `AGENTS.md`); a `grep` option written as an unambiguous prefix (`--qui`, `--cou`, `--exclude-d AGENTS.md`, where `AGENTS.md` is the option's value) is read as the option it abbreviates, `rg` ones are not; a `Grep` result that is empty or says `No matches found` searched nothing; a link that loops back through a `..` component (`alias -> alias/../docs`) leads to no held file; and a `tail` with an invalid value (`--follow=bad`, `--pid=x`, `-s x`) or a count that is not a number is not a stage that passes lines.
