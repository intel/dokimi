### Fixed

- **`process:guidance_read` lists only guidance files the workspace held when the agent started** — a Bash call that holds several reads (`cat a/AGENTS.md; cat missing/AGENTS.md 2>/dev/null`) gives each of them `rc` 0, since its exit does not say which file failed, so `guidance_read` listed a path that never existed. `repo run` now takes the workspace files `guidance.globs` match after the arm is applied and before the agent starts, and keeps a read only when its path is in that set: a path that never existed, a file the arm removed and a file the agent created itself no longer count. A read of a file that is there, the `rc` rules, `unknown_reads` and `tool_calls` are unchanged. A probe path pattern (`/proc/cpuinfo`) on a file that a `grep` or `rg` names after a short option with an attached value ending in a value option's letter (`rg -g*.md x /proc/cpuinfo`) was missed.

### Added

- **`process:guidance_searched` lists the guidance files an agent searched** — `process.guidance_searched` in `result.json` holds the sorted guidance paths (held when the agent started, as for `guidance_read`) that a `grep`, `egrep`, `fgrep`, `rg` or `git grep` part of a Bash call (Claude Code), command (Codex) or `bash` command (Copilot) named as a file operand and showed lines of, and the path of a Claude Code `Grep` call in `content` mode. `guidance_read` keeps its meaning (files printed whole) and `tool_calls` its count. Not counted: `-q`, `-l`, `-L`, `-c`, `--count`, `--files`, a directory or glob operand, stdout sent to a file, a negated or refused command, a pipe into anything but `head` or `tail`, and a search that failed as one search of one file. A relative file after an earlier call's `cd` is dropped and is not added to `unknown_reads`. The `command` and `tool` events carry an optional `searched` list (`repo_event.v1` widened, `docs/events-format.md`), and `repo compare` and `repo report` show a `process:guidance_searched` row beside `guidance_read`.
