### Fixed

- **`dokimi benchmark run` and `benchmark batch` refuse a missing provider key before any model call** — they now make the check `benchmark preflight` makes and exit 2 with the same `missing <VAR> for provider <name>` lines, instead of starting the pipeline, printing tracebacks, exiting 5 and leaving empty directories under `results/`. A CLI provider that is not installed or not signed in is refused the same way, whatever model route it names, and a login that cannot be checked is a warning on stderr. `amazon-bedrock`, `google-vertex` and a `vertex_ai/` or `bedrock/` model route (for example `--provider anthropic --model vertex_ai/...`) are not checked, since they can run on AWS access keys or application-default credentials; a `gemini/` model needs `GEMINI_API_KEY` or `GOOGLE_API_KEY`, and an unreadable `GEMINI_API_KEY` file is refused; another provider's route (`--provider openai --model anthropic/...`) needs that provider's key, and a route off the table (`--provider anthropic --model azure/...`) needs none of the configured provider's when its key is unset. A `file:` `AWS_BEARER_TOKEN_BEDROCK` that cannot be read is refused for a Bedrock answerer, judge or `bedrock/` route whose configured provider has no key of its own; an unset token is still allowed (IAM). `benchmark preflight` applies the same rule.
