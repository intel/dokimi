### Added

- **Versioned releases, starting at 0.1.0** — `dokimi --version` prints the
  version, `dokimi.__version__` exposes it, and the `dokimi run` manifest and the subject
  scorecard `run_manifest` record it as `dokimi_version`, so either of those two results
  can be tied to the release that produced it (other artifacts do not record it yet).
  The version is single-sourced from `project.version` in `pyproject.toml`.
- **Changelog** — this file, built at release time from per-PR fragments in
  `changelog.d/` (`scriv create`).

### Changed

- **Bundled registries and the spec schema live in the package** —
  `products.yaml`, `intents.yaml`, `config/products.yaml` and
  `benchmarks/spec.schema.json` moved to `dokimi/products.yaml`,
  `dokimi/intents.yaml`, `dokimi/config/products.yaml` and
  `dokimi/runner/spec.schema.json`, so an installed wheel carries them and
  works outside a source checkout. A `config/products.yaml` in the working
  directory still overrides the bundled one for `answers generate` and
  `questions generate`. `explore` without `--tasks-root` in an installed
  package now says the bundled tasks need a source checkout, instead of
  finding no tasks.

### Removed

- **The top-level `cli` module is no longer installed** — the wheel used to ship
  `cli.py` as a top-level module, so `import cli` and `python -m cli` worked after
  `pip install`. Use the `dokimi` command, `python -m dokimi` or
  `from dokimi.cli import main`; `python cli.py` still works in a source checkout.
