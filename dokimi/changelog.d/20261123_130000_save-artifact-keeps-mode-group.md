### Fixed

- **`save_artifact` keeps the mode and group of the file it replaces** — a save over a file with mode `0640` in a supplementary group gave the new file the umask mode and the user's primary group, because the tmp file was a new inode. The payload is now published through `dokimi.atomic_write.write_bytes_in_place_or_atomic`: a plain file, a read-only one in a writable directory included, is replaced by rename and keeps its mode and, where the user may give it, its group; a new file still gets the umask mode; a hard-linked or other special file, or a file in a read-only directory, is written in place, as `Path.write_bytes` writes it; a symlink at the path stays and the file it resolves to is replaced. An in-place write is not atomic (a reader can see a partial file), and a file the user cannot write in place raises `PermissionError`. `tools preference` checks `--out` the way the save will write it: a writable file in a read-only directory and a long file name are accepted, a read-only file in a read-only directory is refused with exit 2 before any probe call.
