### Fixed

- **`trace prefilter` no longer lists Markdown scaffolding as rules** — an underlined (Setext) heading, a four-space indented code block and an HTML comment such as a licence header are now skipped, as `#` headings and fenced code already were. A licence comment no longer yields a `kept_protected` row for `Apache-2.0`. `prior to` now counts as an ordering constraint, like `before`, so such a rule is tagged `ordering`. The `novelty` commands share the segmentation: span ids shift on files with these constructs, and a new span kind `comment` appears in their span lists. A `***`, `___` or `_ _ _` rule (with LF or CRLF line endings) ends the paragraph above it and is never a Setext underline, text after a closing `-->` is read as prose, and a comment inside a sentence or list item adds no protection tag, even when it holds a sentence boundary or runs over a blank line. A literal `<!--` or `-->` in inline code (one or more backticks) opens or closes no comment. A code span may wrap over a line break, a sentence cut falls in no code span, and a comment that runs on past its paragraph or list item is a `comment` span of its own, so its text is no part of the rule before it. A rule that such a comment cuts in two keeps its protection tags on both halves. `<!-->` and `<!--->` are complete comments, a comment indented four spaces or more is paragraph text, and a comment between two sentences leaves the second one without the first one's protection tags. The second indented paragraph of a list item stays list content, and a line under a list item is never a Setext heading. Novelty runs on files with these constructs are not comparable with earlier runs: `prior to` adds `ordering`, comments lose their tags, so the protected spans differ.
