### Changed

- **Fail-on flags: one spelling for the warn and fail gates.** `--fail-on-warning` is now `--fail-on=warn` on `repo validate` and `repo budget`. `--fail-on-fail` is now `--fail-on=fail` on `repo scan`, and `--fail-on-error` is now `--fail-on=fail` on `repo inspect`. `--strict` on `eval triggers generate` is now `--fail-on=warn`, and the catalog `trigger-set` tombstone points there. `--fail-on` takes `warn` or `fail` only where the command can gate on that level, so `repo scan --fail-on warn` is refused. The old spellings print the new command and exit 2, so scripts and CI that pass them must change the flag. `--strict` stays on the commands whose gate is a verdict (for example `docs check`, `catalog check`, and the judge and baseline exits), where it is not a plain warn or fail gate.
