### Fixed

- **A Markdown or HTML report with a lone surrogate no longer ends in a `UnicodeEncodeError` traceback** — a name from a JSON or YAML `\ud800` escape, or from a path with a byte that is not UTF-8, in an arm, a library, a product, a question or an artifact reference made `Path.write_text` raise, and the `except OSError` around the write did not catch it. The `.md` or `.html` of `arms run`, `arms plugin-delta`, `arms matrix-run`, `eval score pairwise`, `eval score checklist`, `eval judge agreement`, `explore run --out-md`, `report generate`, `report summary --out`, `skill novelty analyze` and `skill novelty view`, and the dashboard's `save_dashboard_markdown`, is now written with the lone surrogate replaced by `?`, so it stays valid UTF-8; a JSON-style surrogate pair (a high escape followed by a low one) is joined into its character first. The report is published through a temporary file and a rename, so a reader never sees half of it. The bytes of a report whose text encodes as UTF-8 are unchanged.
