### Added

- **`dokimi report summary` merges `cli_output.v1` documents into one summary** (#749, the renderer). It takes files or directories of `*.json` and writes `--format markdown` (a check table and a subject table, usable as a job summary, a PR comment or terminal output), `json` (`report_summary.v1`, with a bundled schema) or `annotations` (`::error`/`::warning` lines). It reads envelope keys only, so a new leaf needs no change in it. A missing, unreadable, malformed or non-`cli_output.v1` input, and a directory with no `*.json` file, stays a row (`not_run` or `invalid`) and makes the overall state bad; it is never dropped or shown as a pass. A document whose status is `budget_stopped`, `partial` or `cancelled` is that state, not a pass, and gets a `::warning`; an unpriced spend shows as `unpriced` and leaves the total empty; the Markdown lists each finding (file:line, code, message, the first 100). It computes no verdict and exits 0 once written: the gate stays each leaf's own exit code. Stdlib only, and it reads no `GITHUB_*` variable.
- **`catalog check`, `catalog eval` and `skill routing` take `--json`** (#749, #94 F2): one `cli_output.v1` document on stdout, with one subject per skill (and per task for `catalog check`). Exit codes are unchanged. `catalog eval --json` leaves a skill outside `--changed-from` unjudged (`verdict: null`, no findings) and points a finding at its `SKILL.md` under the given root. `skill routing --json` is report only (`verdict: null`) and carries `queries_self_derived` next to its scores; its human summary goes to stderr. `skill routing --json` still prints its document when `--max-usd` or a model error stops the run (status `budget_stopped` or `partial`) and then exits non-zero as before; its subject is the loaded skill's name. `catalog check --json` refuses `--format json` and `--jsonl`.
- **A `cli_output.v1` subject may carry `findings`** (`level`, `code`, `message`, `file`, `line`). `catalog check`, `catalog eval`, `repo validate` and `repo scan` fill them; `repo scan --json` puts each failing claim at its file and line and adds the claim counts to `summary`. `report summary --format annotations` gives each finding a `file=`/`line=` annotation, and the Markdown shows the scalar `summary` values of each document.
- **`actions/report`** places the summary: it runs `dokimi report summary` over `out-dir`, appends the Markdown to the job summary, prints the annotations, keeps one sticky PR comment with `comment: sticky`, cut below the comment limit and only a warning when it cannot be posted, and uploads `out-dir`. No parsing and no verdict in YAML. `repo-eval.yml` renders `repo validate` and `repo scan` with the same renderer instead of two inline Python blocks.
