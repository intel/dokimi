### Fixed

- **A `skills.yaml` or a `benchmark --registry` file with a value PyYAML cannot build (a date such as `2026-99-99`) names the file** — `catalog check` says `invalid skills.yaml at <path>: ...` and the catalog evaluator `invalid YAML at <path>: ...`, as for a YAML syntax error, where they gave PyYAML's bare message. `benchmark preflight`, `run` and `batch` read `--registry` as `catalog list|show --kind product` do: a file that is not UTF-8 or not YAML, or that has such a value, prints `Error: cannot read --registry <path>: ...` and exits 2 instead of a traceback, and a missing path or a directory prints `Error: --registry <path>: not a file` and exits 2. A missing file was read as an empty registry (also exit 2, the target not found or `No libraries to run.`), and a directory was a traceback. A pipe, such as `--registry <(cat products.yaml)`, is still read; one that gives nothing but whitespace, as when the command behind `<(...)` fails, prints `Error: --registry <path>: the pipe was empty (did the command writing it fail?)` and exits 2, for `catalog list|show --kind product --registry` and every `--intents` too, instead of reading as an empty registry. A device, such as `/dev/null` or `/dev/zero`, prints `Error: --registry <path>: not a file` and exits 2, where `/dev/null` was an empty registry and `/dev/zero` was read until memory ran out. A name the system cannot look up (too long, or under a directory without search permission) prints `Error: cannot read --registry <path>: ...` and exits 2, instead of a traceback, as `catalog list|show --kind product --registry` and the `--intents` of `catalog list|show|intents` now do.
