### Changed

- **Input and usage refusals exit 2, not 1** — the exit-code table (CLI API v2 §2.6) gives 2 to a missing, unreadable, malformed or unusable input, a flag combination a command refuses, an output file that cannot be written, and a benchmark run or preflight with no provider credential. Exit 1 is left for a verdict or a gate that ran and failed. The messages are unchanged. Scripts that branch on `$? -eq 1` for these cases must also accept 2. Affected: `personas` (approve, discover), `questions`, `eval` (score, ragas, grounding, validity, panel-score), `orchestrate`, `report` (eval, generate, model-compare), `baseline`, `novelty`, `catalog` (and `catalog probe`), `answers`, `arms`, `explore`, `tasks`, `subjects`, `repo` (and `repo run`), `library`, `tools`, `dashboard`, `run`, and `benchmark` (run, preflight, batch). A preflight that fails only on a missing credential exits 2; one that fails on its question-set checks still exits 1.
