### Changed

- **The JSON input flags share one reader and refuse a device.** `eval personas validate --file`, `eval questions generate --personas` and `--topics`, `eval questions analyze` and `review --questions`, `arms run` and `matrix-run --questions`, `report generate --eval`, `tools preference --groups`, `repo scan --baseline` and `catalog trigger-probe --trigger-set` now read their file with `read_json_input`. A device or socket given to one of them (`/dev/zero`, `/dev/null`) exits 2 with `<flag> <path>: not a file`, before it is read; it used to be read in full, and `/dev/null` used to fail as invalid JSON. (`personas validate --file` and `questions generate --personas/--topics` already refused a device; only their message changes.) Their messages take the `<flag> <path>: <reason>` form: `cannot read <path>: <reason>` and `<path> is not valid JSON: <reason>` become `<flag> <path>: <reason>`, `Cannot read <path>` and `Cannot parse <path>` (`personas validate`) become `--file <path>: <reason>`, `cannot load matrix run inputs: <reason>` (`matrix-run --questions` on an unreadable file) becomes `--questions <path>: <reason>`, and `--trigger-set <path>: <reason>` names the file, and a shape error inside the set keeps its `--trigger-set: <reason>` form. The reason is the OS error text (`No such file or directory`), not the full `[Errno 2] ...` string. An empty path exits 2 with `<flag> "": no file given`. Exit codes stay 2, with one exception: a JSON file nested past the decoder's recursion limit now exits 2 naming the file, where `personas validate`, `report generate`, `catalog trigger-probe` and `questions generate --personas/--topics` used to exit 5 with a traceback.
