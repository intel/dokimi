### Fixed

- **`write_json_atomic`, the report `write_json`, `save_atoms`, the routing result, `tools preference --items-out` and `skill novelty items --out` refuse an object that would hold two equal keys** — `write_json_atomic(p, {1: "a", "1": "b"})` wrote `{"1": "a", "1": "b"}`, which a reader loads as one entry; a surrogate-pair key beside its character did the same, and so did a lone-surrogate key beside the key `?` in `write_json_atomic`, which writes a lone surrogate as `?`. The writers now raise `ValueError` and write nothing, as `save_artifact` and `to_jsonl` do (#1054, #1066): a file already at the path is untouched. The two commands that had no handler for it (`catalog routing`, `skill novelty items --out`) exit 2 with `Error: ...` on one line, and `tools preference --items-out` exits 2 as it does for an unwritable path. A payload with no repeated key is written with the same bytes as before.
