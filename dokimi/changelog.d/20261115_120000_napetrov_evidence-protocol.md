### Added

- **`subjects evidence`: each result says when it may be compared.** A result now carries `metric_spec` (unit, range, direction, judged), the `verdict_rule` its verdict follows (`p_adjusted` below `alpha`; stated only for the sign-flip test, since an older `student_t` record also needed Wilcoxon), and `protocol {id, version, digest}` (`dokimi.awareness` version 2): the digest is `sha256` over the canonical JSON of the resolved measurement inputs (judge snapshot, sampling, judge prompt hash, eval-set digest, repeats, test, correction and the number of tests it ran over, thresholds). A protocol id or version this build does not write is never comparable. A missing input or an alias such as `latest` is listed in `protocol.unresolved` and left out of the digest. `comparable`/`non_comparable` say why a result cannot be compared. `dokimi.subjects.evidence_check` holds the consumer checks, with conformance fixtures in `tests/fixtures/evidence_conformance`. Matrix-rollup and scorecard cells now carry the judge the run recorded (`judge_model`, `judge_provider`, `judge_context`, `judge_temperature`, `judge_prompt_sha256`, `judge_resolved_models`). A run that recorded exactly one judge snapshot is resolved to it, whatever judge name was configured; with no recorded snapshot a bare family name (`opus`, `sonnet`) is an alias, and with two the judge is unresolved. A questions file missing from the working directory leaves the scorecard’s `suite.question_set_hash` and the corresponding evidence eval-set digest null. Runs do not record a repeat count, so `repeats` stays unresolved.
