### Added

- **Judged recall for replay tasks** — `dokimi repo hits judge <batch> --judge PROVIDER/MODEL` asks a judge model whether each credited (thread, finding) pair of the batch's `dokimi:review_replay` cells makes the same point (`same point`, `related` or `unrelated`), reading the thread's full comment from the task's gold file and the finding's full text from `answer.txt` rather than the 200-character `matches`. Each fully judged cell gets `hits_judged.json` (`repo_hits_judged.v1`) with the labels, their counts and `recall_judged`, which is at most `recall` since only credited pairs are rescored; the grade is not changed. A judge that runs any answer model of the batch (a CLI alias counting as its family's full id) and a `--labels` entry naming no credited pair, labelling a pair whose thread comment or finding text is no longer the one the sheet holds (compared exactly), or giving one pair two different labels, are refused with exit 2 before any call; `--dry-run` prices the run without a call, and `--max-usd` starts no new call once spent (a cell left gets no file, exit 1), and after a judge reply with no known price starts no further live call, since the cap cannot be enforced on it (that reply still labels its pair, cached pairs still finish, and the run exits 1 only when pairs are left). `dokimi repo hits sheet <batch> --out FILE` samples the pairs for a person to label, `--per-arm` per arm with a fixed `--seed`, and refuses to replace a sheet that has labels, or an existing file it cannot read or parse as JSON; with that file, `--labels` reports agreement and Cohen's kappa per arm, and without it the output says `recall_judged` is uncalibrated. `repo report --hits --json` also gives `grader_failures` and `cells`, the replay cells whose `matches` was read and those whose answer had no findings JSON (a parse error, counted with recall 0).
