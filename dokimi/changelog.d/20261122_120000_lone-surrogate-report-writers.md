### Fixed

- **More report writers write a lone surrogate as `?` instead of ending in a `UnicodeEncodeError` traceback** — a name from a JSON or YAML `\ud800` escape, or from a path with a byte that is not UTF-8, made `write_text` or `open(..., "w")` raise in the Markdown of `docs check`, `docs compare`, `report eval` (the paired page and the one-condition page of a knowledge run), `report model-compare`, `benchmark run` (its report step), `subjects run` (the scorecard `.md` and the task-runs `.md`) and `tasks run`, and the `except OSError` around the write did not catch it; for `subjects run` and `tasks run` the JSON artifact was saved first and only the `.md` was lost. These reports are now written like the ones of the earlier fix: the lone surrogate becomes `?`, a JSON-style surrogate pair is joined into its character, and the bytes of text that encodes are unchanged. A symlink, a hard-linked or special file is still written in place, and an unwritable path still exits as before.
