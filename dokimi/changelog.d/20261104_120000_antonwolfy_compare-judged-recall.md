### Added

- **Judged recall in `repo compare`** — `dokimi repo compare <batch> --baseline ARM --metric judge:recall_judged` compares judged recall from `repo hits judge`'s `hits_judged.json` across arms, as the row `metric:judge:recall_judged`, next to `--metric recall` from `grade.json`. A cell counts only when its file is `repo_hits_judged.v1`, names the cell's own cell, task, arm and model, and holds the `recall`, `n_threads` and credited (thread, finding) pairs its `grade.json` has now, with the comment and message cuts each pair records (`repo hits judge` now writes the match's `comment` and `message` with each pair, so a regrade that rewords a thread or finding within the 200 characters the grade keeps makes the file stale; a later change is not seen); stale (regraded since judging), unjudged (`recall_judged` null), a cell with no gold thread, a cell `repo hits judge` never judges (a grader failure, a grade without `matches`, another grader: `not_judged`), misplaced and unreadable files are left out of the task's mean and counted per arm (`--json`: `judged_cells`; the text prints one line per arm with a cell left out). Any other `judge:` name, and a `judge:recall_judged` no selected cell reports, are refused with exit 2, the latter saying to run `repo hits judge` first unless every cell has no gold thread or is `not_judged` (a rerun writes the same null, or no file; the per-arm line leaves its hint off then too); the text notes that compare cannot tell whether the judge was calibrated.
