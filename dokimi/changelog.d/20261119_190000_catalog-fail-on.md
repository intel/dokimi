### Added

- **`catalog check --fail-on-code CODE`** — repeatable; the scan exits 1 when a finding with that code is left after `--ignore`, at any level, so an edit loop or a gate can fail on a `warn` or `note` such as `description-no-when` or `link-missing`. An unknown code is a usage error, as with `--ignore`, and so is a code the scan never reports in its mode: the cross-catalog codes (`duplicate`, `name-conflict`, `mirror-drift`, `description-near-duplicate`) with `--per-skill`, `link-dead` and `package-not-found` without `--online`. `--strict` is unchanged. With `--json` the skill's subject has verdict `fail`; with `--per-skill --resume` the current selection applies to the rows kept, and a `fail-on-code: <skill> has <codes>` line says why the scan failed. The whole-catalog text output prints the same line. The option prefix `--f` no longer abbreviates `--format` (it matches `--fail-on-code` too); write `--format`.
