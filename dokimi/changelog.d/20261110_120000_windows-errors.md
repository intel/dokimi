### Fixed

- **Windows: a symlink loop, an unwritable output and a non-UTF-8 path in git's listings are read as on Linux** — a loop is EINVAL with WinError 1921 there, and `runs show`, `RunsRoot.exists`, the repository link walk and the suite glob took it for another error instead of an absent or looping path. The `--out` pre-flight checks of `novelty routing`, `catalog trigger-probe` and `arms matrix-run` asked `os.access`, which on Windows reads only the read-only attribute and is true for any directory, so paid work ran before the write failed; they now try the write (an existing file opened for append, a directory given a new file that is removed again if it can be) and refuse as before with exit 2. `skill_sha`, `suite_hash` and `catalog eval --changed-from` raised `UnicodeDecodeError` on a path git prints with a byte that is not UTF-8; on Windows that byte is now replaced, except that `catalog eval --changed-from` checks every skill (with a `selection_note`) when a changed path is not valid UTF-8 or holds an encoded lone surrogate, since the replaced name could be another skill's. The write pre-flight opens its probe file write-only, so a directory whose new files deny read access is still accepted.
