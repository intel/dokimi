### Fixed

- **A lone surrogate in an argv entry** — `process.run(['echo', 'n\ud800'])` raised `UnicodeEncodeError` from `subprocess` before the child started, so a prompt passed as an argument (`claude -p <prompt>`) with a JSON or YAML `\ud800` escape stopped the run. The entry now reaches the child with each character `os.fsencode` cannot encode as `?`, and a `\ud83d\ude00` escape pair as its character, as on stdin; `U+DC80..U+DCFF` on POSIX stay, since `os.fsdecode` makes them of a non-UTF-8 file name. `Completed.argv` holds the text sent; an entry that needed no change is unchanged, and a `bytes` entry still runs as given.
- **A lone surrogate in a task instruction** — `DockerSolverHarness` wrote `prompt.txt` with a strict UTF-8 encode, so an instruction with a `\ud800` or `\udcff` escape raised `UnicodeEncodeError`. The file now holds the instruction with an escape pair joined and a lone surrogate as `?`, as the Harbor export writes it, and `claude -p` gets that same text.
- **A lone surrogate in a package name** — `catalog check --online` built the registry URL of a package named in a skill with a strict `quote`, so a name with a `\ud800` or `\udcff` escape raised `UnicodeEncodeError`. The lookup now quotes the name with an escape pair joined and a lone surrogate as `%3F`; the registry answers 404 and the usual `package-not-found` warning follows.
