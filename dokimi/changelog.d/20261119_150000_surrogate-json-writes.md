### Fixed

- **A lone surrogate in a cached completion, an exported row, an artifact or a fidelity golden** — `caching.store_response`, `datasets_export.to_jsonl`, `save_artifact(..., ensure_ascii=False)` (the `report_qa` sidecar and the `.rejected` copy of a refused payload) and `fidelity.write_golden` encoded their JSON strictly as UTF-8, so a value with a `\ud800` escape raised `UnicodeEncodeError` (`store_response` promised never to raise). All four now join a surrogate pair (`\ud83d\ude00`) into its character and keep a lone surrogate as its `\ud800` escape, so it reloads as the same string, a cache hit replays the text the call returned, and an object key holding one never collapses onto a `?` key. An object holding the pair key `\ud83d\ude00` beside the key of its character (`😀`) is refused with a `ValueError` by `to_jsonl`, `save_artifact(..., ensure_ascii=False)` and `write_golden`, since a reader keeps one of the two; `to_jsonl` encodes one row at a time into a temporary sibling file and replaces the destination only after every row is written, so a refused or failing export leaves an existing file as it was and creates none, and memory is bounded by a row, not by the export; a symlink at the destination (dangling or not) is followed, so the link stays and its target is replaced. Files whose text encodes as UTF-8 keep their bytes, except line endings on Windows: the text-mode writes of `to_jsonl`, `save_artifact` and `write_golden` ended lines with CRLF, and they now end them with LF.
