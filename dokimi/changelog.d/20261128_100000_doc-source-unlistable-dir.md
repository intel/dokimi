### Fixed

- **`local:` and `okf:` doc sources refuse a directory they cannot list instead of reading a smaller tree** — both clients listed the tree with `rglob("*")`, which skips a directory it cannot list without an error, so a source holding `a.md` and `sub/b.md` with `sub` at mode `0o111` gave `a.md` alone and `check_connection()` said `True` (a root at `0o111` gave no docs and a "no doc files found" warning). `get_library_docs` now raises `MCPConnectionError` naming the directory, as it does for a missing path, `check_connection()` returns `False` with a warning that names it, and `require_local_doc_source` (`eval questions generate`, `benchmark preflight`) exits 2 with `cannot list <directory>` rather than falling back to default seed topics. A tree that can be listed gives the same files, a directory with no doc files still gives a warning and no docs, and a file that cannot be read is still skipped. `docs/adding-doc-source.md` says what each case does.
