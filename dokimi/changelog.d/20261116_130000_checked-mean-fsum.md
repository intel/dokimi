### Fixed

- **Mean of float deltas no longer depends on the Python version** — `checked_mean`, which gives the `repo compare` summary mean (`sign_flip_summary`) and the per-question means of the model comparison, added floats with `sum()`, which compensates only from Python 3.12: `[1e307] * 6 + [-1e307] * 6` gave `-2.079e290` on 3.11 and `0.0` on 3.12. It now sums with `math.fsum` (exactly rounded), so the mean is the same on every version and agrees with the interval. Integer-only inputs are still summed as exact integers, and integers mixed with floats as exact fractions (`[2**53 + 1, -(2**53), 0.0]` gives `1 / 3`, not `0.0`). A mean that is not affected by rounding is unchanged. The range check on the sum of magnitudes is exact too, so values whose exact total passes the float range (`0x1.fffffffffffffp+1023, 2**969, 2**969`) raise the requested error with its context on Python 3.11, not a bare `OverflowError`. With an integer among the values that range check sums the magnitudes exactly too, so integers whose exact total fits the float range are taken (`fsum` would round each to a float first and overflow; `main` refused them when a float came first, as in `[0.0, m - 2**970 + 1, 2**970 - 1]` with `m` the largest float). The mixed `[m, 2**969, 2.0**969]`, whose exact total passes the range, is refused now, where `main` returned the mean of the rounded total.
