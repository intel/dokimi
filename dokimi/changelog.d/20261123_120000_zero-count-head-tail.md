### Fixed

- **`guidance_read` no longer lists a file a shell `head` or `tail` read with a count of zero** — `head -n 0 AGENTS.md` and `tail -c 0 AGENTS.md` exit 0 and print no line, but the walker took every file operand of `head` and `tail` as a read. A count that prints nothing (`-n 0`, `-c 0`, `-0`, `--lines=0`, `--bytes=0`, `head -n +0`, `tail -n -0`) is now no read; `head -n -0` and `tail -n +0` print every line and stay reads, and so does `tail -f -n 0`, which prints what is appended. A command prefixed with `POSIXLY_CORRECT=1` (or run through `env POSIXLY_CORRECT=1`) ends its options at the first file, so `POSIXLY_CORRECT=1 head AGENTS.md -n 0` prints the file and stays a read; a `-` operand ends them too (`POSIXLY_CORRECT=1 head - -n 0 AGENTS.md` stays a read, and `POSIXLY_CORRECT=1 tail -n 0 AGENTS.md -f` is no read, as `-f` is a file there), and `env -i` or `env -u POSIXLY_CORRECT` drops the variable (`POSIXLY_CORRECT=1 env -i head AGENTS.md -n 0` is no read). An `export POSIXLY_CORRECT=1` earlier in the same call, in its own shell (not a subshell, pipeline or background job), counts the same way until an `unset POSIXLY_CORRECT` or `export -n POSIXLY_CORRECT`. (#1008)
