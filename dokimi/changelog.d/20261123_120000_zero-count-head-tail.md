### Fixed

- **`guidance_read` no longer lists a file a shell `head` or `tail` read with a count of zero** — `head -n 0 AGENTS.md` and `tail -c 0 AGENTS.md` exit 0 and print no line, but the walker took every file operand of `head` and `tail` as a read. A count that prints nothing (`-n 0`, `-c 0`, `-0`, `--lines=0`, `--bytes=0`, `head -n +0`, `tail -n -0`) is now no read; `head -n -0` and `tail -n +0` print every line and stay reads, and so does `tail -f -n 0`, which prints what is appended. A command prefixed with `POSIXLY_CORRECT=1` (or run through `env POSIXLY_CORRECT=1`) ends its options at the first file, so `POSIXLY_CORRECT=1 head AGENTS.md -n 0` prints the file and stays a read; a `-` operand ends them too (`POSIXLY_CORRECT=1 head - -n 0 AGENTS.md` stays a read, and `POSIXLY_CORRECT=1 tail -n 0 AGENTS.md -f` is no read, as `-f` is a file there), and `env -i` or `env -u POSIXLY_CORRECT` drops the variable (`POSIXLY_CORRECT=1 env -i head AGENTS.md -n 0` is no read). An `export POSIXLY_CORRECT=1` earlier in the same call, in its own shell (not a subshell, pipeline or background job), counts the same way until an `unset POSIXLY_CORRECT` or `export -n POSIXLY_CORRECT`. An `export` or `unset` after `&&` or `||` counts only when it runs: after `true`, `:` or `false` the walker knows whether it does (`true || export POSIXLY_CORRECT=1; head AGENTS.md -n 0` is no read), and after any other command it may have, so the file stays a read when either state prints it. A function named `export` or `unset` shadows the builtin, `command unset` and `builtin export` run it, and `export -n POSIXLY_CORRECT=1` assigns the value without exporting it, so a later `export POSIXLY_CORRECT` exports it. Every command of a brace group that `&&` or `||` skips is skipped too (`false && { :; unset POSIXLY_CORRECT; }` changes nothing), a function named `true`, `false` or `:` has an exit the walker does not know, `command --`, `command -p` and `builtin --` run the builtin after them (`command -v` runs none), an `export` or `unset` with a redirect (`export POSIXLY_CORRECT=1 >/dev/null`, also glued to the operand: `export POSIXLY_CORRECT=1>/dev/null`) still counts, but not for sure when the redirect may fail to open (`unset POSIXLY_CORRECT </missing` may not run, so both states are kept; one to `/dev/null` (also `<>/dev/null`) or a copy or close of descriptor 0, 1 or 2 cannot fail, while `2>&9` fails when descriptor 9 is not open; a redirect on a brace group, `{ unset POSIXLY_CORRECT; } </missing`, is opened before its body runs, so a failing one keeps the state from before the group), a `NAME=value` word or the `time` keyword before it runs it in this shell (`X=1 export POSIXLY_CORRECT=1`, `time export POSIXLY_CORRECT=1`, also through `command` or `builtin`: `X=1 command export POSIXLY_CORRECT=1`, and `command builtin export POSIXLY_CORRECT=1` past a function named `builtin`; `env export` and `X=1 time export` run a program and change nothing), an option the builtin refuses (`unset -z`, `export -zn`) changes nothing, the `}` that closes a brace group has no exit of its own (`true && { false; } || unset POSIXLY_CORRECT` runs the `unset`), `unset -f` and `export -f` name a function and leave the variable, and a bare `export POSIXLY_CORRECT` marks the name so that a later `POSIXLY_CORRECT=1` is exported. A here-string on the export (`export POSIXLY_CORRECT=1 <<<x`) is one redirect that cannot fail, a command after `then`, `else` or `do` may not run (`if true; then export POSIXLY_CORRECT=1; fi; head AGENTS.md -n 0` keeps the read when either state prints it), `NAME+=value` assigns like `NAME=value` (`export POSIXLY_CORRECT+=1`, `POSIXLY_CORRECT+=1 head ...`), `unset` takes names only (`unset POSIXLY_CORRECT=1` is refused and changes nothing), `declare -x` and `typeset -x` export like `export`, and `set -a` (or `set -o allexport`) exports what is assigned after it until `set +a` (or `set +o allexport`), also past an `unset` or `export -n` (`set -a; unset POSIXLY_CORRECT; POSIXLY_CORRECT=1; head AGENTS.md -n 0` stays a read). Redirects count in order: a copy of a descriptor an earlier redirect closed fails (`unset POSIXLY_CORRECT 1>&- 2>&1` does not run the `unset`, while `2>&1 1>&-` does), and every command between a `then` or `do` and its `fi` or `done` may not run, not only the first (`if false; then :; unset POSIXLY_CORRECT; fi` leaves both states). A brace group that closes a descriptor a command in its body copies (`{ unset POSIXLY_CORRECT 2>&1; } 1>&-`) fails before the body runs, so the state from before the group is kept; `declare +x POSIXLY_CORRECT` (also `typeset`) drops the export mark, and a readonly name refuses a value, so `declare -r POSIXLY_CORRECT; export POSIXLY_CORRECT=1; head AGENTS.md -n 0` is no read.
